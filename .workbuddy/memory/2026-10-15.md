需求：前端页面移动端自适应，可用手机 / iPad 浏览器访问。

### 布局骨架改造（关键）
- 旧版是「`fixed bottom-0` 播放条 + 学习页 `calc(100vh - 109px)` 魔法数字」，那些数字按桌面顶栏 61px、

  **刻意不写 `maximum-scale`/`user-scalable=no`** —— 允许缩放是无障碍要求。

## 修复：手机端顶部信息条被压成竖排单字（22:40~23:00）

用户报：「已听写 / 已掌握 / 平均最佳被挤成竖排单字」。位置在 `StudyPage` 学习页顶部条（不是听写面板）。

### 根因（两层，缺一不可）
1. **直接原因**：`StudyPage.tsx` 里那一组写成了 `<span className="flex items-center gap-1">` ——
   **不换行 flex 容器**。里面的「已听写」「· 已掌握」「· 平均最佳」是**裸文本**，
   各自成了 flex item，被压缩时下限是 **min-content = 一个汉字宽** → 竖排。
   （实测：组 125×83px，「已听写」3 行 × 11px、「· 已掌握」4 行、「· 平均最佳」5 行）
2. **诱发条件**：右侧按钮组（播放 / 笔记 / 工具）是 `shrink-0`，约 190px；
   外层单行 `flex` 里中间栏（`min-w-0 flex-1`，basis 0）**只能拿剩下的 90px** —— 连标题都被截断。
   ⭐ 所以「只让那组允许换行」是治不好的：90px 下会变成 5 行小字。

### 修法（三处，缺一不可）
1. 顶部条外层 `flex` → `flex flex-wrap`（允许换行）
2. 右侧按钮组加 `w-full justify-end sm:w-auto` —— **手机上强制独占一行**（basis 100% 才会真的换行；
   只加 flex-wrap 没用，因为 [←][中间栏][按钮] 加起来仍放得下，flex 不会主动换行），
   `sm:` 起恢复 `w-auto` 回到单行
3. 那一组改成 `flex flex-wrap`，且**每段各自 `whitespace-nowrap`** 包成独立 span

**效果**：组 125×83 → **216×17（单行）**；中间栏 90 → **283px**；顶部条 144 → **99px**（反而更矮，舞台净赚 45px）；
标题不再被截断；无横向/纵向溢出。桌面端 `sm:` 断点回到原单行布局，截图确认无变化。

### 定稿几何（链 C）
H = W = 830（1:1，**被恒等式逼出来的正方形**）
SW = 196 (=H/φ³)｜R = 98 (=SW/2，端头/外凸转角)｜R_FIL = R_DIP = 75 (=SW/φ²，内凹转角/蒂窝)｜R_LEAF = 121 (=SW/φ)
L_W = 438 = 2SW + SW/φ³（横笔平直段 = SW/φ³ = 46）｜GAP = 75 = SW/φ²｜FRUIT = 317 = SW·φ
★ 恒等式（精确）：`L_W + GAP + FRUIT = (2SW+SW/φ³) + SW/φ² + SW·φ = SW(2φ+1) = SW·φ³ = H = W`
　（因 1/φ² + 1/φ³ = 1/φ、2 + 1/φ + φ = 2φ+1 = φ³）
柚子：椭圆 317×274.5（**宽:高 = 2:√3**，压扁＝与「苹果」拉开的关键）、蒂窝半角 20°（弧半径 75）、
　　　叶 弦长 196 = SW、弧半径 121、轴 **arctan(φ) ≈ 58.28°**、基部埋入果内 17.67（果身覆盖叶根，靠外轮廓分界，无需描边）
　　　叶尖朝左是**必然**的：朝右会越出外框。绘制顺序：叶 → 果 → L。
favicon 独立几何：H=W=960、GAP 收一档到 SW/φ²=87 换柚子变大到 332（16px 下果 5.53px）
配色：松墨 #0E3B34 + 柚黄 **#DB9E28**（比 #E4A72E 深一档，纸底对比 2.14:1）＋深底 #0B2A26 / 果提亮 #F0C25C
另交付 **表情版**（眼 r=SW/φ⁴、笑弧 r=SW/φ、线宽 SW/φ⁴）作备选，明示代价：形状数 4→7 超 F §1 建议、24px 以下失效。

### 反复试错的教训（重要）
1. **半圆（对径点）的叉积为 0** → `arc_cmd` 必须支持显式 sweep，且大弧要显式 large-arc。
   柚子果身第一版画成月牙，就是「300° 大弧」被判成了 60° 小弧。**椭圆弧用 `A rx ry ...` 直接写，不要硬套圆半径。**
2. **「果 + 粗梗 + 叶」三件套失败**：梗像塞子、缩小糊成一团 → 改为**叶根埋进果内、果身覆盖根部**（2 个形状搞定）。
3. **果身必须压扁**：正圆 + 叶 = 「黄苹果」，且与横笔端头同尺寸同高 → 像「线头长了个球」。压成 2:√3 才读成柚。
4. **内凹转角半径直接决定「横笔会不会掐腰」**：R_FIL = SW/2 时平直段 = 0，横笔端部成「鸭子嘴/药丸」；
   收一档到 SW/φ²（与蒂窝同档，半径级仍只有 3 档）→ 平直段 46、脚部正常。
5. 链 B（L_W=2SW、果=SW·φ）数学最漂亮但平直段为 0 → 脚部报废；链 A（L_W=H/φ、果=SW）脚部最好但果偏小。
   **最终取链 C**：间隔收一档，把宽度让给平直段，果同时保持大。以后改这三个宽度前先算平直段。
6. 断言目标必须**跟着链走**：色链换成 C 后，blueprint/spec 里手写的 `1:φ⁴` 目标立刻报 38% 误差 —— 把手写目标也换成参数化。

### 选色方法（这次验证有效，可复用）
先算 HSV/相对亮度/对比度把候选缩到 5×5，**但要落成真实标志的并排矩阵用眼睛定** ——
`#DB9E28(H39.6) → #EDC62A(H48.0)` 单看数值不直观，渲染出来「琥珀→正黄」的差别一眼可辨。
深色底必须**提亮**：浅底粉（L0.34）直接放深底会闷，改用 #FFA8C8。

### 顺带修掉的两个真缺陷（都写进了交付物）
1. **favicon 的「独立几何 / 柚子放大」说法早已失效**：切到链 C 后，主标果 = SW·φ、间隔 = SW/φ²，
   而 favicon 仍是 L_W=2SW+GAP → 果/H **0.3458 < 主标 0.3819**，即 favicon 反而更小，16px 实测 5.53 < 6.11px。
   **修法**：favicon 改成与主标**同比例**（FRUIT=round(SW·φ)=367、GAP=SW/φ²=87、L_W=506），
   它存在的唯一理由改为**画布整除性** —— 外框 960 可被 16/32/48/64 整除（主标 830 不能，16px 缩放系数 51.875 → 半像素虚边）。
   新增断言 `H % 16|32|48|64 == 0`。**并把 16px 承诺写实**：笔 3.78 / 果 6.12 可辨，**间隔 1.45px 会并拢**（物理下限，明说，不假装）。
   教训：**换几何链之后，所有「小尺寸/降级」类文案必须重算**，否则会留下反向的假声明。
2. **preview.html 里小图标被全局 CSS 拉变形**：`.css` 里有 `svg{display:block;width:100%;height:auto}`，
   导致 App 图标（100px 瓦片里塞 66px 标志）与浏览器标签页 16px 图标被拉满容器、圆角切掉笔画。
   修法：加 `svg.fix{width:auto;height:auto}` + `mark_inline(..., extra="class='fix'")` —— 靠选择器特异性压过全局规则，不用 !important。
   ⚠️ 注意 `mark_inline` 的 `extra` 是**单引号**属性（`extra="class='fix'"`），grep 时别按 `class="` 搜。
