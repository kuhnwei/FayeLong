### 🔴 QA 抓到的 MEDIUM（已修）
`GET /api/sessions/{id}/report` **未按 `submitted_at` 设闸** → 未交卷就能读到 `explanation`（注释写着「交卷后才下发」，代码没 gate）。
- 修法：闸放**领域层** `services/papers.py`（409「尚未交卷」），API 层只做异常映射。放 API 层的话，将来「导出 / SSE / 批处理」都会绕过
- **顺带把 `ResponseOut.detail` 整个删掉**（它含听写的 `expected` 与写作的 `reference_answer`）→ 判分明细只经 report 下发，比「序列化时记得删」可靠
- `grading` 会话**允许读** report（200、`pending>0`、写作题分数 NULL）：已交卷，前端要能轮询；这里也 409 的话前端分不清「还没交」与「还在判」
- 闸的判据是 **`submitted_at is None`（单向锁定标志），不是 status** → 未来「边答边判」只要交卷前不置 `submitted_at` 就不会绕过

### P4-4 默认降级（ADR 那个「付费点」冲突的解法）
`FAYELONG_GRADING_PROVIDER=off` **默认** ⇒ 零付费、离线可用，产出参考范文 + 评分标准 + 自评清单，`status='degraded'`（**成功态**，job `done` 而非 `failed`）。想真批改配 `FAYELONG_GRADING_*` 即可，不改代码。
- 缓存 key = `sha1(question_id + "\x00" + JSON(归一化作答, sort_keys))`；**降级结果不入缓存**（否则「临时关 provider」会被固化成永久结论）
- 密钥三处出口全堵：只从 `Settings` 读、唯一去处是 HTTP 头；`mask_secret()` + `scrub()`；用例断言异常/日志/缓存 payload/settings 四处无原文
- **`ungraded ≠ degraded`**：前者「判不了」，后者「判了但走降级包」；**`pending` 只数「还会被 worker 判出来」的题**，`ungraded` 不算 —— 否则前端为一道永远判不出的题永久轮询
- 外部调用用**标准库 `urllib.request`**（`httpx` 只在 dev 依赖里）→ **零新增依赖**
- 日配额落 `settings` KV；「网络失败也计 1 次」是保守口径（防持续失败绕过上限）；⚠️ 读-改-写非原子，IO 池并发可能**偶尔少计**（绝不多计），个人自用可接受
